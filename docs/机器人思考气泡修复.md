# 中央机器人思考气泡缺失：排查与修复

日期：2026-09-12。

## 根因

`scripts/asset-kit-v2.mjs` 的 `consoleDesk()` 原先先创建 `Coordinator`，随后对整个总控台执行 `compact(g)`。`compact()` 按材质合并所有后代网格，并执行 `p.clear()`，把独立的机器人组一起移除。

原始 `studio.glb` 能看见机器人外形，但没有名为 `Coordinator` 的节点。客户端的 `getObjectByName('Coordinator')` 返回空，气泡创建分支和机器人动作分支都无法执行。这是“有显示代码，但实际从不冒泡”的直接原因。

## 复现证据

- 检查原始 GLB 的 JSON 节点表，`Coordinator` 数量为零；机器人材质已合并为 `Console_*` 网格。
- 在 Chromium 中加载真实 GLB，注入确定的 `reasoning-delta`，场景正常渲染且六个员工动作已匹配，但机器人节点检查失败，页面无思考气泡。
- 修复资产后，同一个浏览器回放显示“思考中：先检查配置文件，再核对页面布局。”，截图位于 `tmp/coordinator-bubble-check/thinking.png`。

浏览器用例使用合成事件，不调用外部模型；它证明实际渲染与气泡挂载已恢复，不等同于本轮完成了已安装宿主的真实模型联调。

## 改动

- 总控台先合并静态家具，再添加独立 `Coordinator`；机器人内部单独按材质合并。
- 重新生成 `console.glb`、`studio.glb` 与资产清单。三角面数量保持不变，完整场景增加一个网格。
- 资产校验要求两个资产各有一个可独立移动且包含可见几何体的 `Coordinator` 组。
- 客户端诊断加入机器人节点是否找到及气泡文字；缺节点时明确提示更新资产。
- 新增真实 GLB 浏览器回归，检查思考文字可见、结束后清空和卸载清理；更新客户端构建产物。

## 验证命令

```powershell
node scripts/build-assets.mjs
node scripts/verify-assets.mjs
node scripts/build-client.mjs
node scripts/check-coordinator-bubble.cjs
```

本次上述命令均通过。浏览器检查沿用现有脚本的 Playwright 路径约定，可通过 `STUDIO_PLAYWRIGHT_PATH` 指定依赖。

## 生效范围与剩余边界

修复产物位于项目目录。已安装插件使用安装目录中的资源，必须更新其资产并重新挂载工作室视图，才会加载独立机器人节点；单独更新客户端脚本不能恢复旧 GLB 中已经丢失的节点。

本次没有修改模型阶段策略：思考结束后，气泡随撰写、派活或空闲状态改变；短于快照采样周期的思考仍可能错过。该时序限制与“机器人节点完全不存在”不同，不是本次完全不显示的根因。多会话模型状态隔离继续按升级计划处理。
